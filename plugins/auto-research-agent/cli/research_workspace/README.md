# Read-only research workspace

This first #80/#82 slice projects an existing Stage 1 package into an English
HTML workspace, notes, a graph, a complete catalog and bibliography. It does not
change canonical research records or rebuild the original deliverable. English
is the first-load UI language; simplified and traditional Chinese remain available.
Source titles, authors, claims, quotations and reasons retain their original text.

`project_package` requires an externally supplied SHA256 for the outer
`package_manifest.json`. It checks file inventory and bytes, the inner manifest,
record identities and source/claim bindings before projecting them. The default
`byte-inventory` projection explicitly does not attest original runtime replay.
Full semantic replay belongs to the existing deliverable validator in its pinned
runtime and is outside this read-only adapter. Failed replay stays failed; the
adapter cannot substitute byte checks for that result. Projection establishes no
scientific sufficiency, independent evaluation or execution authority.

The view reuses the four reference assets from #88 at exact head
`085f363179a79375fc8e3590dda9725e25eda71a`. Supply that checkout's
`plugins/auto-research-agent/references/research-workspace` as `--reference-root`.
Asset hashes are checked and bound to the output receipt. This is an explicit
Draft reference dependency; core acceptance of replacement coverage and native
execution remain separate gates.

Set `PYTHONPATH` to the plugin's `cli` directory and run:

```text
python -B -X utf8 -m research_workspace PACKAGE_ROOT NEW_OUTPUT_DIR \
  --project-id PROJECT_ID \
  --expected-manifest-sha256 OUTER_MANIFEST_SHA256 \
  --reference-root PINNED_REFERENCE_DIRECTORY
```

Use a new output directory outside Git for each snapshot. Open its `index.html`
in a browser; it reads the saved index without fetching papers or making model
calls. The `wiki` directory also preserves readable Markdown notes. Notes and graph edges retain exact work/version identity, field provenance
and input bindings. BibTeX selection only joins entries generated by the existing
canonical producer. Filtering cannot silently redefine the all-record export.

All six stages remain navigable. Execution controls stay disabled, including
Stage 2: displaying review-only evidence cannot approve its import or start.
Missing metadata, unavailable source content, partial/unverified claims and open
coverage remain explicit. An absent supplement means Top 3 is pending, not that
three findings have been synthesized. Roles do not imply citations or shared
methods; classification tags without supplied concept IDs remain unmapped.

This slice does not implement persistent sessions, pending native answers,
scoring, selected reruns or two-topic native Windows acceptance. The accepted
core APIs are reused in subsequent slices. New search intake, scoped browser
consent, live permissions and budgets must pass their existing gates. No frozen
package, rubric, baseline result, attempt or old Draft is changed by rebuilding.

Run deterministic regressions with the repository's pinned test environment:

```text
python -B -X utf8 -m unittest discover -s plugins/auto-research-agent/tests -p "test_research_workspace*.py" -v
```

Private papers, source text, actual indexes and snapshots never belong in Git.
Public fixtures are synthetic. Rendering success and byte checks do not prove
P1-P3 quality improvement or actual native execution.

### Accepted private repair overlay API

`project_package` accepts `repair_root`, `expected_repair_manifest_sha256` and
`expected_repair_review_sha256` together. External hashes bind the private
candidate manifest and independent delta review. Every listed member and exact
source passage is checked before a copied WorkspaceIndex v2 is returned. The
unchanged v1 schema and default projection remain supported.

The overlay retains original claims, compound judgments, unknown coverage,
failed attempts and the original rejected review. Atomic revisions and core
findings keep separate denominators and typed provenance. Recovered abstract
content does not establish full-method access; presentation grants no Stage 2
import, execution or scientific-quality upgrade.

The CLI accepts the same three optional repair arguments and emits English
HTML, version-bound notes, a complete bibliography and editable Excel/CSV.
`closeout/` contains the accepted atomic mapping, core findings, input/runtime
bindings and Traditional Chinese status summary. `repair/` retains the checked
acceptance and source-evidence snapshots. All outputs remain outside Git.
Opening, exporting or rebuilding this view performs no research or scoring.

Saved-source reading is an explicit offline API: `source_rerun.build_rerun` accepts an original v1/v2 index, saved-source root, new private output and exact local parser hash. It preserves source bytes and historical attempts, records new extraction/access failures, and binds runtime versions. It performs no acquisition or judgment. This reader slice does not activate v3 attachment, UI or formal Stage 2 import.

`source_rerun.attach_rerun` accepts that private manifest only with an external
SHA-256. It verifies the complete artifact inventory, saved response and
extracted-text bytes, parser-bound attempt IDs, work/source/version identities,
locators and metadata provenance before returning WorkspaceIndex v3. Original
claims, coverage, Unknowns, failures and source receipts remain unchanged.
Abstract extraction cannot become full text, and the overlay cannot authorize
research, new acquisition, scientific judgment changes or Stage 2 import.

The CLI accepts `--source-rerun-root` with its external manifest SHA-256 and
emits the v3 overlay as read-only HTML, per-work Wiki notes, Excel/CSV,
Markdown and BibTeX. Every exported source byte remains private and bound to
the accepted manifest. Rebuilding a saved v3 view reads only those artifacts;
it does not rerun the parser, acquire sources, score quality or alter the
original scientific record.
