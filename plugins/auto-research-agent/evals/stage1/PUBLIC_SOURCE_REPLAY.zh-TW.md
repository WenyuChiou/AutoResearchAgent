# Stage 1 / T1：保存來源的公開介面重播

目前 `_validate_fetch` 會再次檢查保存的來源。舊實作直接匯入
`research_hub.source_fetch.validate_source_fetch`，但 research-hub 沒有把這個
Python 模組承諾為穩定介面。現在沿用呼叫者已核對的指令與執行環境，改用
已文件化的 `source validate RESULT --json`。不新增搜尋器，也不取得新論文。

依據 research-hub PR #140 的合併版本
`929bdd6d963acf4be5bc9d80ce3c5c0a0f77a834`，此離線介面核對原始檔案、雜湊、
重新抽取的文字和位置。評估器明確接受 `source-fetch-validation/v1` 報告；
未來格式若改變，需更新介面與回歸測試，不能默默接受。

每次重播在來源的 `validation/replay-events.jsonl` 追加兩筆觀察：先登記指令與
輸入雜湊，再保存退出碼、原始 stdout/stderr 的十六進位表示、雜湊和結果。
十六進位可以保存非 UTF-8 錯誤訊息。成功重查會追加紀錄；失敗、逾時、
中斷或改動過的紀錄會阻止再次執行，保留原因，診斷修復後使用新檔案庫。

這些追加紀錄是新的驗證觀察，不是重新搜尋或重新請模型判斷。原始來源、
第一次取得與驗證的 receipt 不被覆寫。需要完全不寫入的原始實驗保存區時，
先建立新的診斷目錄，再執行重播，保留原始保存區及其雜湊。

例如，一份原文的位置被改寫，即使有人重新計算外層雜湊，公開驗證器仍會
從原始資料重新抽取並拒絕不一致；退出失敗與原始訊息會保留下來。
網路取得失敗的來源仍可有結構有效的報告，這不會使其成為可用證據。

本改動是 T1 的來源介面修復。它不完成每個中央主張的語意審計，不替代
T2 的完整判準單元與彙整，也不改 frozen rubric。新增程式改變 evaluator
bundle 雜湊；舊 freeze 只能使用其原始程式版本，新診斷與正式實驗須另行鎖定。

`test_source_replay.py` 覆蓋公開指令、原始資料、版本／格式绑定、追加紀錄、
逾時、錯誤和禁止盲目重試。`test_sources_v31.py` 保留呼叫者的執行環境、
來源取得、重建與失敗語意檢查。通過這些工程檢查不表示 P1–P3 科學品質提升。
