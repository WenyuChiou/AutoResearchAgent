# 第一輪控制情境：查核行為與科學判斷分開驗收

以下是公開的 synthetic 開發情境。資料中的事實是測試用設定，不是實際論文結論，
也不是正式 A/B 的答案清單。給定查核結果後，CLI 應保存正確處置；這不能證明
LLM 會自行發現問題。後續非正式預演才測 agent 是否能從來源辨別這些問題。

| 情境 | 已知事實 | 可接受的處置範圍 | 不能宣稱的事情 |
|---|---|---|---|
| 1. 增量已被完成 | 給定前例已完成候選宣稱的相同增量 | 修正到有據的不同增量；沒有剩餘價值可淘汰 | 只換標題就說首次提出 |
| 2. 有檔案、缺變數 | 可下載的資料字典沒有必要的月度變數 | 改問年度問題、找合適材料或暫存 | 下載成功代表研究可回答 |
| 3. 有價值、超資源 | 最小原設計仍超過已確認的時間或成本 | 縮減但保留價值，重新查核；否則暫存 | 忽略成本或暗改使用者目標 |
| 4. 方法簡單但足夠 | 簡單比較能回答重要問題且有合適資料 | 推薦進入詳細設計 | 因不複雜而淘汰，或保證突破 |
| 5. 關鍵未知 | 必要材料或核心前例尚無可查核證據 | 保留 unknown 與具體下一步 | 把 unknown 當 0 分事實或當已通過 |
| 6. 全部有問題 | 每個候選都有未解硬阻塞 | 零推薦，交代原因與下一步 | 零推薦自動滿分；反過來硬湊推薦 |
| 7. 證據損壞 | 作品、版本、原文或已知 hash 不符 | 拒絕無效證據；分開報 evaluator failure | 評估器故障等於受測者研究品質差 |
| 8. 等義改序／修辭 | 實質内容與證據相同，排序或文字長度不同 | 品質分數不因表面變化無據提高 | 視圖排序測試通過即證明 live judge 無偏差 |

另測混合組合：D1 可推薦、D2 應淘汰。D2 的低可行性不能把 D1 的推薦刪掉，
也不能直接限制整份評估的分數。反之，D1 的高分不能掩蓋 D2 未處理的重大錯誤。

## 如何判讀測試結果

- `test_stage2_checker.py` 測已提供查核結果的接受、拒絕、修訂與匯出。
- `test_stage2_evaluation.py` 測獨立評分格式、來源綁定、未知、分歧與配對規則。
- 這些測試不呼叫模型、不搜尋文獻、不測科學發現能力。
- 第 8 項的真正評分穩定性、兩位 judge 的一致性與跨題目適用性，仍須另做校準。

後續 agent 診斷需保存輸入、來源、實際輸出、問題發現／修正／殘留數與成本。
先凍結可接受處置範圍，再看結果；不要求兩組提出同一個研究方向。
