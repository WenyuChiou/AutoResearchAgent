# Stage 2 正式比較前的四個門檻

我們要確認的是：AI 真的做得了研究工作、評分沒有看錯對象、整個流程能跑完，
最後才比較加上 harness 是否更好。程式測試成功不等於四個門檻都成功。

| 門檻 | 白話意思 | 驗收證據 |
|---|---|---|
| 1 原生能力與隔離 | 能讀寫、搜尋、請子 agent 幫忙，也不能偷看到答案或另一組結果。 | 實際設定、原生工具結果、事前建立的隔離測試檔、版本與 hash。 |

## 目前證據與限制

原生啟動的實測找到 Windows 設定問題：沒有啟用 Windows sandbox 時，
要求 workspace-write 仍可能得到 read-only。啟用受限 token sandbox 後，
不呼叫模型的啟動回應已修正；獨立 Git 根目錄也避免載入上層 AGENTS.md。
但這個 sandbox 不支援 deny-read，不能因此宣稱隔離通過。

另外，空白 CODEX_HOME 仍可能找到個人的 `.agents/skills`。準備程序會依
真正的 skills/list 清單停用個人 skills，保留原生 bundled 能力；A、B 都要
重新盤點，只允許研究 harness 是兩組的差別。

新版 preflight 會核對真正的工具結果。只看到「Permission denied」文字、
找不到測試檔、收到 JSON 或程式正常結束，都不夠。缺少證據就保留 blocked，
不幫系統猜成通過。[操作與限制](../../references/stage2-runtime-preflight.md)。

正式 A/B 尚未因這些程式修改而啟動。四關全通過並凍結共同投入政策後，
才按 A→B、B→A、A→B 執行。P5、P6 各至少兩對改善且零退步，P4 零退步，
B 不增加重大錯誤，才支持本案例的改善主張。三對結果不代表統計顯著或跨領域通用。
