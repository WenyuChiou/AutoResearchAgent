# Stage 2：從研究證據到可選方向

版本：Stage 2 general v2。狀態：experimental / implementation-only。
本輪是固定候選查核切片；完整方向生成、live judge 與正式 A/B 尚未完成。

## Why：要解決什麼

文獻摘要寫得完整，不代表提出的研究機會成立。方向有價值，也不代表團隊取得到
必要資料。Stage 2 要交付有證據、限制與取捨的選擇包，讓研究者決定是否進入詳細設計。
它不承諾頂會成果、研究突破，或正式研究必定成功。

## What：研究工作與邊界

完整流程：確認需求與證據 → 文獻比較與綜合 → 研究機會 → 候選方向 →
證據挑戰與初步可行性查核 → 修正／補查／暫存／淘汰 → 選擇包 → 人類選擇。

比較至少回答：研究問什麼、材料與方法是否可比、結果一致或衝突的條件、限制如何影響
下一步。欄位依題目決定；不強迫每個領域都填人口、國家或 LLM 欄位。
研究機會可來自重要未知、矛盾、測量問題、理論限制、有價值的重複或獨立驗證。
探索研究不必假裝有事前假設；簡單方法也可以解決重要問題。

## 開放發想與方法創新

說明修訂：`open-method-ideation-v1`。既有 Stage 2 v2 rubric、分數及門檻不變。

Stage 2 也要容許 AI 主動提出有理由的新看法、新方法或新研究設計。候選可以來自
文獻缺口、挑戰既有假設、重組已知方法、跨領域借用、新機制，或重新研究過去失敗的
方向；這些是例子，不是封閉的分類清單。不要求先找到一篇明說「這裡有缺口」的文章。
新方法本身可以成為研究問題，而不只是拿既有方法補一個應用缺口。

因此保留兩條平等的發想入口：

| 入口 | 從哪裡開始 | 候選需要說清楚什麼 |
|---|---|---|
| 改良既有方法或設計 | 既有版本的限制、失敗、成本或適用範圍 | 改哪裡、為何可能改善、相對原版及其他方法增加什麼價值 |
| 提出新概念、方法或設計 | 挑戰假設、提出不同機制或重新表述問題 | 新想法的依據、與前例的差異、能用什麼方式檢驗 |

兩條路都接「查前例與反證 → 五面向查核 → 修正／暫存／淘汰／推薦 → 使用者選擇」。
入口不是先後順序或互斥分類；改良可以發展成新概念，新概念也可收斂成可做的改良。
不強迫每輪兩種都要有；不因標成「全新」就加分，也不因只是改良就扣分。

發想時先用自然語言、草圖或簡短推導探索，不強迫研究 agent 一開始填深層 schema、
湊固定數量，或逐步照同一條思考路線。允許保留高潛力但尚不成熟的構想供補查，
不因尚未達推薦門檻就在發想階段刪掉。原生工具仍可使用；範圍、成本及權限限制仍適用。
這是指引，不表示本輪已實作自動候選生成或測得創造力改善。

形成候選後，再說清楚：已知依據、AI 新提出的部分、預期作用機制、最接近方法、
最小比較或消融，以及可能失敗的條件。把文獻事實、推論和待檢驗構想分開；
引用支持設計動機，不代表它已支持新方法的成效。構想完成後才由無工具擷取步驟
整理紀錄；保留原始提案，擷取失敗不能丟棄它或補造證據。

所有候選仍走機會、價值、可回答性、材料與執行五面向。新方法尚未證明有效，是研究
要回答的問題，不自動構成推薦阻塞；可以推薦一個有據且可檢驗的設計，不能宣稱已成功。
相反地，不知道必要資料能否取得、關鍵前提是否成立或驗證是否可做，仍須保留 unknown，
不能藉「創新」繞過 gate。預期成效放在候選問題／限制，不能把假設填成已驗證 findings。

例如可提出「依外部錯誤訊號決定是否進行修正」的 agent 設計，再比較既有方法與
相同預算的替代設計。這只是未驗證構想示例，不宣稱新穎；須補查前例、額外成本及
錯誤訊號失效時的後果。增加模組、換名字或引用熱門方法，不會自動增加研究價值。

| Stage 2 查核 | Stage 3 才完成 |
|---|---|
| 是否有可信的回答或推進途徑 | 最終研究設計、估計與分析程序 |
| 材料、必要變數、粒度與存取條件是否合適 | 完整資料清理、篩選與切分 |
| 是否有合理 baseline 與驗證途徑 | 最終比較組、獨立驗證與統計安排 |
| 最小研究是否符合資源條件 | 詳細排程、成本、依賴與停止規則 |

小型 probe 只回答會改變投資決定的疑點。例如讀資料字典可確認是否有月度消費。
幾次 LLM 呼叫只能證明某條流程能執行，不能證明行為符合真實人口。

## How：第一輪輸入與交付

輸入是已確認的 ResearchBrief、資源限制、固定來源快照、原文片段、比較結果、
未解事項與一組候選。ResearchBrief 沿用既有版本與使用者決定；不自行換國家。
來源保留 work、version、hash、證據層級與原文位置。Metadata 不當成 findings 證據。

第一輪由 Codex／研究者提供語意查核，再用 CLI 驗證、保存與產生選擇包。
程式不從關鍵字猜科學價值，也不把 JSON 通過稱為研究有效。原生搜尋、閱讀與
程式執行能力仍可使用；research-hub 是可重用工具，不是所有查核的必經入口。

新增候選與查核兩種紀錄。候選 ID 穩定、版本連續，舊版本不覆寫；查核綁定具體版本。
修訂後必須重新查核，不可沿用舊版 PASS。每次處置有理由、來源與下一步。
沒有推薦是合法結果，但必須說明查過什麼、為何不足以及有用的下一步。

| 發現問題 | 下一步 |
|---|---|
| 缺少 closest work 或反例 | 定向補查，保留疑點；不重跑無界 Stage 1 |
| 增量已被前人完成 | 修正定位；若仍無價值則淘汰 |
| 缺資料、必要變數或權限 | 查替代材料、縮減問題或暫存 |
| 超過時間／算力／API 資源 | 提出保有科學價值的最小版本；不可只換措辭 |
| 需要改變使用者研究範圍 | 提出選項，等待使用者決定，不暗中縮小 |

本輪 CLI 保存下一步，不自動搜尋、開無限 subagents 或執行研究實驗。
Stage 1 handoff 繼續保留原來的 not-started；明確啟動 Stage 2 才建立自己的 run。
Stage 3 不會因某個候選通過而自動開始。人類可以選擇一個或多個方向。

## Example

候選 D1 說要估計月度消費改變，但資料字典只有年度總額。查核應指出這個差異，
將 D1 修成年度問題或暫存。若變成年度問題，保留 D1 v1、建立 v2，再重新檢查
問題價值與可回答性。不能把「檔案下載成功」當成可行性通過。
