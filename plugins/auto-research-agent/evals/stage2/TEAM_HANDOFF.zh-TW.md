# Stage 2 接續分工與完成條件

先讀 [科學契約](SCIENTIFIC_CONTRACT.zh-TW.md)、[checker rubric](DIRECTION_CHECKER_RUBRIC.zh-TW.md)
及[獨立評估流程](INDEPENDENT_EVALUATION_PROTOCOL.zh-TW.md)。目前是 experimental /
implementation-only。第一輪的改善聲明固定為「功能已驗證，研究品質改善尚未證明」。

## 已授權第一輪

核心組定義契約、指標與判定；工程模型在不同模組實作共同封包／離線評估和固定候選
checker。核心組整合、測試、獨立 review 並經 fork PR 交付。模型完成的工作不能寫成
另一位真人組員已完成。每個 commit 保留 Why、What、Tests、AI contribution、Human verification。

| 順序 | 產物 | 驗收 |
|---|---|---|
| PR 1 | 三份契約、歷史診斷、版本化 P4–P6、共同來源封包、離線 evaluator | 舊 v1 不變；來源、未知、處置獨立性與配對負向測試通過 |
| PR 2 | 固定候選 checker、修訂與處置歷史、選擇包、skill | 可重建一個 run；舊版查核不能通過新版候選；有阻塞不亂推薦 |
| 後續 PR | 文獻綜合、候選生成、補查與非正式預演 | 先依本頁拆成單一可測任務，不直接開正式 A/B |

## 組員接續的三個小任務

1. **固定輸入的原生診斷。** 從已確認的 brief 和可靠 Stage 1 封包建立中立輸入。
   用原生 Codex 產生自然語言比較與候選；記錄觀察、原始輸出定位與待驗證問題。
   不把完整 Stage 1–3 的 run01 問題全部歸因於 Stage 2。
2. **接候選生成。** 優先重用 literature-triage-matrix、gap-to-topic 與原生工具。
   依科學契約的開放發想原則，容許新方法、假設挑戰及跨方法組合；不以「文獻已明說
   存在缺口」作為入場條件，也不強迫每次提出某一類或某個數量的點子。先自然推理，
   再查前例、作用機制、比較方式與成本。舊 skill 的分類與量表不直接變成限制或分數。
   自然語言研究完成後再由無工具擷取步驟整理成共同封包。不要把 evaluator 的答案、
   judge 分數或正式測試結果傳回生成器；多個可用方向或零推薦都合法。
   區分待檢驗成效與缺失的必要前提；只有後者因證據不足而阻擋推薦。保留擷取前原稿。
3. **有界補查。** 每次只處理會改變選題的疑點；記錄目的、工具、成本、來源、結果及
   未解事項。修訂候選後重新查核；資源或必要範圍改變交 Eric 決定，不偷偷更換。

每個任務先列 reuse／wrap／extend／build-new 及理由。若需要修改 research-hub 或
其他 repo，回報外部 PR URL 與不可變 SHA，讓核心組一併審查。不要直接修改 upstream。

## 回傳給核心組

- PR URL、base/head SHA、commit 說明，以及外部依賴 PR／SHA。
- 一句「改善了什麼、證據是什麼、還沒證明什麼」。
- 原始測試輸入、來源 hash、實際命令／結果、候選版本、查核與選擇包。
- 無法取得的證據、已知限制、失敗與修正紀錄、時間／工具／模型成本；未知成本標 unknown。
- skill 改動附簡單報告：情境、命令、預期、實際、限制。

組員提交與修正，核心組審查及 merge。測試綠燈不取代研究判斷。

## 進正式 A/B 前仍需完成

凍結兩組相同起始證據、自然語言 prompt、模型與原生能力；非正式預演量測並凍結
總投入政策。補齊 native capture、執行／模型呼叫憑證、R1/R2 隔離及 ADJ、具名 audit
與等義改序校準。接通來源查核與成本紀錄後才能申請正式 readiness。

正式比較在使用者選題指導之前結束；P5/P6 各至少兩對改善且零退步，P4 零退步，
B 無新增重大錯誤。完整方向生成 A/B 與固定候選診斷分開報告。
預計第 1 週契約與診斷、第 2 週最小切片、第 3 週修正與預演；這是目標時程，
不代表現已完成正式測試。Stage 1 收尾可以平行進行。
