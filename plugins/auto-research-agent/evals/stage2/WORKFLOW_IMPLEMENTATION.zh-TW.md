# Stage 2 完整流程：實作與驗收

本文件是完整流程的實作契約，不代表整個流程已經完成。已存在的固定候選 checker
和 Markdown 提案報告繼續可用；新增能力逐個通過測試、live 預演後才提高 readiness。
P4–P6 的七項判準不變，沒有新增人工標準論文清單。

## 要完成什麼

確認需求 → 比較文獻 → 開放發想 → 初篩 → 獨立挑戰與可行性查核 →
補查／修正 → 提案與問答 → 使用者選擇 → Stage 3 交接。

改良既有方法、新概念和新機制，都可以進入這條流程。研究可以是探索、理論、
方法、重複或驗證；不強迫寫假設、不要求固定點子數，也不因方法複雜就加分。
美國人口老化案例用來開發和預演，不能寫成通用程式的預設條件。

## 為什麼需要新快照

想像原來的資料夾有兩篇文獻，查核者根據它們推薦 D1。後來找到第三篇反例，
這時不能把第三篇塞進舊資料夾，卻仍拿舊的「通過」當作查過三篇。

新流程保留原資料夾，建立下一版，記下新增什麼、可能影響哪些方向。
第一版採保守做法：證據更新後，所有候選都重新等待查核；不自行猜哪個不受影響。
每次來源、版本、引文和 hash 都要重新驗證。範圍改變仍需使用者決定。

## 如何保留 agent 的自由

研究 agent 先用自然語言、草圖或推導討論；原生搜尋、閱讀、程式與子 agent
仍可使用。之後另開無工具的擷取步驟，把已有內容整理成可檢查紀錄。
原文先保存，擷取失敗不刪除研究成果，也不能補造原文沒有的文獻或理由。

比較要交代問題、對象、尺度、方法、條件及限制。不能直接比較就說清楚。
同一研究多份報告、共用資料與二手轉引要標示，不能把篇數當獨立證據數。
新構想應分開說明已有事實、推論、可能機制與尚未證明的效果。

## 何時查核與回退

五面向仍是機會成立、潛在價值、可回答性、材料及執行可行性。缺乏證據是
unknown，不等於零分；不適用要有理由，不能拿來躲避查核。
新方法會不會有效，可以是研究問題；拿不到必要材料或沒有可驗證途徑，不能推薦。

挑戰者和可行性查核者先保存各自初評，再看別人的判斷。沒有 reviewer、
呼叫失敗、尚未完成，都不是同意。能查原文或資料字典的問題直接查，
只有影響選題且有證據可辨的分歧才辯證。改判要指出新證據或原判斷錯在哪裡。

初篩沒入選的點子也保留。每批抽查最接近入選的一個，再用保存的 seed 抽查另一個；
不足時全查。這用來發現錯殺，不能宣稱找到所有盲點。
最後可推薦、修正、暫存或淘汰；零推薦也合法，但要有原因和下一步。

## 使用者拿到什麼

聊天先給方向比較、推薦理由及待決問題；完整內容保存在可修改 Markdown 和
同資料產生的英文 HTML。包含書目、文獻角色、支持與反對證據、五面向查核、
成本估算依據、修改歷史、未知，以及什麼新證據會改變選擇。

「選擇包準備好了」與「使用者選好了」分開保存。使用者可要求比較、縮減、合併或
重啟；文件修改要成為新版本並重新檢查受影響部分。真正選定後，Stage 3 接手詳細
方法、資料處理、比較組、驗證和排程；發現關鍵不可行時帶證據退回 Stage 2。

## 開發分工與交付順序

| 順序 | 工程工作 | 模型責任 | 本項驗收 |
|---|---|---|---|
| 1 | Workflow、來源版本與 action record | Terra 盤點，主模型定接口，Sol 實作 | 補查不覆寫、舊判斷失效、完成單元可核對後重用 |
| 2 | 比較、開放發想、無工具擷取 | Sol；主模型整合 | 保存原文，拒絕虛構來源及錯引，兩條入口均可用 |
| 3 | 獨立初評、盲點抽查、補查與修訂 | Sol／主模型 | 缺席不算同意，反證會使受影響方向重查 |
| 4 | 問答、Markdown／HTML、Stage 3 交接 | Sol；Luna 做已定義的 fixtures 與連結核對 | 舊版選擇不能套新版，報告和紀錄一致 |
| 5 | Live runner、獨立評估與正式準備 | Sol；主模型凍結及審查 | 原生呼叫證據、judge 隔離、完整配對資料 |

模型由執行當下的 canonical router 決定。最多兩個實作 agent 同時寫不同檔案；
共享接口、科學規則、治理與最終判斷由主模型負責。組員實作和修正，核心組 review
及 merge 到 WenyuChiou fork。每個 commit 保留 Why／What／Tests／AI contribution／
Human verification，每個 PR 說明 Why／What／How／Example 和尚未證明的部分。

## 怎麼知道它有用

1. 程式測試：假設輸入正確，記錄、版本、gate 和恢復是否照設計執行。
2. AI 診斷：不事先告訴答案，看 agent 能否發現已有前例、不可比結果、共用資料、
   必要變數缺失、不同機制同結果，以及多方向超過總資源等問題。
3. Live 預演：美國老化案例和一個非人口題目實際走流程，量測錯誤與成本。
4. 正式 A/B：同樣 Codex、輸入、原生能力與事先固定的投入政策，比較有無 Stage 2
   harness。A 也能搜尋和叫子 agent；不為了凸顯 B 而削弱 A。

獨立 evaluator 先看內容，再看處置。R1、R2 彼此隔離，分歧才用 ADJ；必要 audit
由 Eric 具名覆核。缺必要來源、評分或覆核，就報 inconclusive。
P5、P6 各三對至少兩對改善且零退步；P4 零退步；B 不新增重大錯誤。
unknown 為 null，不縮分母、不合成總分。成本另報，三對不代表統計顯著。

## Readiness 與限制

目前新增 workflow 契約以 `implementation-only` 開發。真實搜尋、模型調用隔離、
來源語意核對與正式六次 A/B 必須另附可重建紀錄，不能由 JSON 驗證通過推論。

[獨立評估流程](INDEPENDENT_EVALUATION_PROTOCOL.zh-TW.md)。
