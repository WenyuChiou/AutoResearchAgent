# 研究方向 checker：五個問題

這是 production 查核規則，不是 harness 的外部 A/B 分數。
候選本身的性質、查核判斷品質、最後選擇包是否有用，必須分開記錄。

| 面向 | 0：有證據不成立 | 1：部分充分 | 2：足以进入詳細設計 |
|---|---|---|---|
| opportunity | 核心增量已被完成或前提被反證，且未修正 | 有研究機會，但最接近工作或邊界未充分處理 | 前例、已知／未知、增量、適用條件與削弱證據清楚 |
| value | 與聲稱影響不符，沒有可成立的貢獻 | 有受益對象，但貢獻與影響路徑不完整 | 指出改善哪種理解、測量、驗證或決策及其理由，不靠複雜度 |
| answerability | 提議的方法／觀察無法處理所問問題 | 可回答途徑合理，仍有關鍵未定細節 | 有可辨別結果的觀察、推導或比較，並交代不能支持的結論 |
| materials | 已確認必要材料、變數、粒度或權限不符且無替代 | 有資料線索或部分適合材料，仍有待補條件 | 關鍵研究材料適用且存取條件已查，替代與限制明確 |
| execution | 最小版本超出資源且無可行替代 | 大致可做，仍需補依賴、估算或風險 | 最小研究、必要能力、時間與算力／API 估算有據，能進入詳細規劃 |

`unknown` 表示證據尚不足以判斷，score=null；不可硬塞成 0 或 1。
`not-applicable` 需要具體理由，score=null；例如純理論工作未必需要觀測資料，
但仍須檢查理論前提與可用推導工具。缺乏證據不能假裝不適用。
已明確不成立時可以提早停止，未做的面向保留 unknown 與停止理由。

每個 assessed 項目都有 evidence IDs、rationale、blocking 與下一步。
引用存在只證明可追溯；語意是否支持判斷仍由獨立 evaluator 查核。
單純宣稱「我驗證過」不能代替來源。

## 處置

- `recommend`：適用的關鍵檢查足以進入詳細設計，沒有阻塞或未決範圍變更。
  第一輪 gate 要求所有適用面向為 assessed=2；這不是科學成果已獲驗證。
- `revise`：有可描述的修正與下一步；新版本保留父版本，重新查核後才可能推薦。
- `park`：目前有未知或資源依賴，說明解除條件。
- `reject`：有來源支持的不成立理由；不是因為題目不華麗。

高價值不能抵銷不可回答或取得不到必要材料。未知的關鍵依賴阻擋推薦。
需要人類選擇地域、材料或優先順序時，另外列出待決事項。

## Example：低分候選可以對應好判斷

資料確實沒有必要變數，materials=0；checker 因此合理暫存，可能代表查核品質很好。
不能把 materials=0 直接當成外部 P6=0。
相反地，全部淘汰也不自動得到 P6=2；還要查淘汰理由、是否忽略可行替代，
以及最後是否留下有用的選項或下一步。

本輪控制情境驗證程式分流與紀錄。尚未測出 live AI judge 的一致性、風格偏差，
或真實研究方向的品質改善；這些限制保留至後續校準與 A/B。
