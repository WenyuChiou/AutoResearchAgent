# Stage 2 前例定位：先說清楚前人做到哪裡

前例定位不是找一篇看起來相似的文章，也不是證明世界上沒有人做過。
它要回答：前人已完成什麼、我們重複什麼、可能多了什麼、還不知道什麼。
最接近的前例可以是一組研究。發現原構想已有前例並正確修正，也可以是
好的定位；是否值得做及材料是否可用，由另外的查核面向判斷。

## 工作流程

1. 讀取已確認的研究需求與目前候選，列出可能的增量。
2. 按問題、作用機制、方法、對象及驗證方式搜尋；使用同義詞、跨領域
   名稱、非 LLM 方法、引用鏈及反例。重用 `gap-to-topic` 與 Codex 原生能力。
3. 閱讀相關原文與上下文，分清作者的方法與文中引用的前人研究。
4. 比較前例的已完成工作、重疊及差異；重要資訊不足時保持未知。
5. 修正候選及定位，保存新快照；讓獨立查核者及外部評分者看新版證據。

已找到回饋架構，不代表參數已由實證辨識。探索性研究可以研究明示的
條件與假定機制，不能因此宣稱真實預測或因果效果。簡單方法不是淘汰理由。
沒找到研究、查得不夠及有據支持差異，必須分開說。

## Opt-in packet 2.4

`Stage2Packet` 2.4.0 延伸 2.3 的文獻、來源及比較表，新增
`prior_work_reviews`。舊版不改寫。版本升級建立新 run，保留原 run 與歷史。
未完成研究時可以是空陣列；缺少目前候選的定位紀錄，正式內容門檻保持草稿。
原生 controller 另外保存 `needs-prior-work` 補查節點及綁定完成紀錄。
研究 agent 補查並建立新快照後，只有非定位內容仍相同且新版定位完整，
才恢復獨立查核；不重做已完成的發想，也不把缺少定位當成 PASS。
來源與回執使用同一份不可變輸入目錄，恢復時重新核對 snapshot、manifest 與 bytes。

每份 `Stage2PriorWorkReview` 1.0.0 綁定目前候選 ID、版本、候選內容 hash，
以及整份 sources／evidence 的 canonical hash。定位、查過的範圍、停止理由、
未解事項、實際搜尋與前例比較共同保存。`partial`／`bounded-complete`
表示記錄中的查核範圍，不表示全球搜尋完整、科學核准或 P5 得分。

搜尋紀錄保存 need、query、實際工具引用、結果／空結果／失敗／未知，
以及有 hash 的相對路徑回執。計畫中的 query 不算執行。批次搜尋的回傳
不能冒充每個 query 的獨立命中數。回執核對保存的觀察，不認證搜尋服務
真的執行；真實執行證據仍是原生工具與呼叫紀錄。

每筆比較綁定 work／version 與 evidence IDs，使用 closest、method-comparator、
contrary 或 boundary 角色。證據層級、來源網址、位置及引文從既有來源推導，
不能另填一組較好的值。Metadata 只能作搜尋線索，不能支持方法或 findings。
取得失敗不變成「沒有前例」；摘要不冒充全文，局部檢查不證明全文不存在。

來源或候選有變，舊定位與舊分數不能直接套用。舊記錄留在舊快照；新版
重新建立定位並查核。版本、作品、原檔、回執或 hash 錯配會拒絕。

## 使用者看到什麼

每個方向先顯示一張表：**前例／已完成工作／重疊／差異／證據與限制**。
定位結論及會改變選題的未知保持可見。原文位置、搜尋歷史與 R1／R2／ADJ
評語按需展開；書目連回既有文獻庫，不再堆一份 DOI 清單。
搜尋回執連結由交付端指定保存位置，沒有有效位置時只顯示路徑，不猜連結。

同一份已驗證資料產生 Markdown、proposal HTML 與 Wiki。它們引用同一
候選及來源版本。獨立查核 view 1.2 只給目前候選的定位，不給其他 reviewer
或外部 judge 的分數。舊 view 1.0／1.1 保留原有行為。

## 評估與停止

沿用未修改的 `P5V3.PRECEDENT`：0＝已觀察錯誤／缺失，1＝部分充分，
2＝定位充分有據；必要證據不可取得時依 rubric 留 null。
表格完整不自動加分，正確承認重疊也不自動減分。
R1／R2 獨立評全部九項，分歧交 ADJ；保存原評語及必要具名覆核。
本項達到 2 且覆核完成，才通過本輪診斷門檻。
找不到合法關鍵原文時保存限制與阻塞，不能重複評到 2 為止。

程式測試查錯配、篡改、摘要界限、失敗狀態及三種交付一致性。
它們不證明研究品質改善；本項診斷也不替代正式三組 A/B。
