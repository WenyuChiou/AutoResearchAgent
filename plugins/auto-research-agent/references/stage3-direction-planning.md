# Conditional direction input

The Stage 3 consumer accepts a pinned Stage2DirectionPlanningIntent and the
existing verified advisory package. The trusted Host must separately verify the
current project, receipt, source frontier and candidate versions; artifact
consistency cannot authenticate a person or make a formal selection.

The context retains preferred candidates, original SQs, assessments, evidence,
resource constraints, source-global unknowns, pending scope questions and user
conditions/unknowns separately. selected_options stays empty,
human_selection stays pending and execution_authorized stays false. Missing
source SQs cannot be filled by the consumer.

The generic prompt retains every original value. A sole $ key references an
integer index in a shared table; $literal escapes source objects with reserved keys.
Expansion must reproduce the original context hash. The existing 48,000-byte
context limit is unchanged; oversized or unmapped contexts need clarification.
DirectionPlanningJobs wraps the existing planning journal and single-dispatch
state machine, finite positive adapter deadline and existing request-size bound.
Project, method and original key identify separate output directories.
Preparation, inspection and replay invoke no callback; explicit
run uses the configured callback once. Failed raw output and provenance remain
saved; uncertain attempts use the existing explicit reconciliation rules.

Stage3DirectionPlanningResult retains one row for each original question_ref,
including materials, method, design, validation, analysis, interpretation,
unknowns and minimum deliverable. It is a conditional draft, not a selected plan,
scientific acceptance or evaluation subject. Host/UI integration and real native
planning remain unverified.

The Host adds mode=direction-intent to the existing planning API. Its key is
stage3-direction- plus the saved intent hash; current project/source bindings
are checked before dispatch and publication. Read, prepare, inspect and recover
never call the planner. Missing source questions or an oversized context return
needs-information, visible planning_blockers and no default_request. The saved
preference is retained. An identical complete input left before journal creation
is reused; a mismatched or partial input remains an explicit failure.

The API retains the original per-question materials and conditional result for
the Wiki presentation slice. Saved jobs must still match the current Host model,
adapter and source bindings; recovery availability uses the existing trusted pin
map. Source unknowns and user conditions remain separate. The target is a Stage 3
planning job; agent_conversation_connected=false. Deployment, Wiki integration
and native/scientific acceptance remain separate; execution_authorized=false.

The Wiki presentation joins each original question to its own recorded materials
and conditional method, design, validation, analysis and result interpretation.
It separates source unknowns, user conditions and missing mappings. Common
resource fields have plain labels; nested original details remain expandable.
Three-language copy keeps direction preferences and conditional drafts distinct
from formal selections. Reading or changing language dispatches nothing; explicit
actions reuse the saved typed request and key. Original raw values remain in the
receipt view. Deployed/native/scientific and whole-flow acceptance remain unverified.
