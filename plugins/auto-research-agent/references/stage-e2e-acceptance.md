# 各研究 Stage 的 E2E 驗收契約

契約版本：`stage-e2e-acceptance-v1`。適用於本 fork 的所有研究 stage。
這是 Eric 已確認的專案要求，供組員與 AI 持續使用；不是已完成執行的報告。
既有 schema、validator、rubric、權限及凍結實驗規則繼續適用。
新要求尚未有程式支援時，明示待實作，不能靠手填完成旗標通過。

## 完成代表什麼

每個 stage 都要驗證：**實際輸入 → 必要研究步驟 → 完整交付物 → HTML
實際操作 → 下一 stage 匯入**。程式或 CI 通過，只證明該次測試的行為。
完整研究 E2E 與正式 A/B 分開驗收；一般使用者不必自行跑 A/B。

每個必要節點保存輸入與來源版本、實際呼叫／操作、輸出、結果及證據位置。
有條件的補查、修訂或辯證按實際需求觸發；不為了填滿清單製造問題。
不適用的節點須說明原因。節點失敗、未取得、零結果、unknown、待覆核與
阻塞分開記錄；缺席 reviewer 不算同意。必要工作漏跑時不得宣稱完成。

原始紀錄與失敗保留。恢復只重用仍匹配且驗證成功的單元；新來源或科學
內容修訂建立新快照與影響清單，重新查核受影響部分。舊 PASS、選擇或
評分不能冒充新版驗證。未知成本保持 unknown，不填零。

## Stage 1：從需求到可接手的文獻包

接收需求 → 確認研究範圍與正式文獻數 → 搜尋／篩選 → 全文讀取及身分、
版本核對 → 證據整理與 coverage 檢查 → 筆記、圖譜及各格式匯出 → HTML
實際操作 → Stage 1 交付與 Stage 2 匯入。

正式文獻數與範圍依本次使用者決定記錄，不固定所有題目的國家或篇數。
無法取得全文時保留實際來源層級與失敗；摘要或 metadata 不升級為全文。
達到篇數不能代替 claim 與 coverage 查核。筆記、圖譜和匯出使用同一版
來源及紀錄；檢查實際檔案內容與連結，不只數檔案。

Stage 2 匯入時驗證實際收到的原包、manifest、brief、來源、claims 與
接受範圍。review-only、continue、unknown 與排除理由一起傳遞；明示的
partial／exploratory acceptance 不代表 Stage 1 證據已充分。旧包不能稱為新版。
細節沿用 [Stage 1 交付契約](stage1-research-deliverable.md)。

## Stage 2：比較、形成方向、查核與交付

| 節點 | 必須驗證的工作與交付 |
|---|---|
| 需求與匯入 | 核對已確認 brief、限制與 Stage 1 版本；保留未知與接受範圍 |
| 比較規格 | 根據題目及代表文獻定義比較面向，說明它與研究選擇的關係 |
| 文獻比較 | 文獻總覽＋主題比較矩陣；各格有來源，分開不可比、未知、不適用及明確不存在 |
| 開放發想 | 保留原始构想，允許改良既有設計或新概念；區分文獻事實、推論與待研究成效 |
| 初篩與抽查 | 保存處置理由，依既定政策抽查未入選候選；不因方法簡單而淘汰 |
| 獨立查核 | 挑戰者與可行性查核者先存獨立初評，再處理實質分歧；判斷必須有據 |
| 必要補查 | 對會影響選題的前例、反證、前提或資源疑點有限補查，保存實際搜尋與失敗 |
| 修訂與重查 | 新快照、候選版本、影響清單與改判原因相符；重新查核受影響方向 |
| 選擇包 | 方向比較、各方向 proposal、必要資源表、取捨、阻塞、未知與下一步 |
| 外部評估 | 同版內容的 R1／R2、必要 ADJ 與具名覆核；保留原始評語及證據位置 |
| 格式與 HTML | Markdown、HTML、Wiki 投影與結構化資料版本一致，實際閱讀與操作可用 |
| 使用者選擇 | 真實問答與當前方向選擇綁定使用者看過的報告版本；等待選擇不假造確認 |
| Stage 3 匯入 | 原始 Stage 2 包、選定候選版本、來源、資源、限制與未解事項可重新驗證 |

比較欄位隨主題而變，不強迫理論研究填人口或資料欄位。不同名稱但相同
機制、同名但不同設計、共用資料或轉引研究，都要在比較中辨識。
空格、未找到研究或勾選數量不能直接證明 gap 或研究價值。

五個內部查核面向是機會成立、潛在價值、可回答性、材料可行性、執行
可行性。它們與外部 P4–P6 九項評分分開。沿用
[科學契約](../evals/stage2/SCIENTIFIC_CONTRACT.zh-TW.md)、
[checker](../evals/stage2/DIRECTION_CHECKER_RUBRIC.zh-TW.md)及
[v3 評估規則](../evals/stage2/STAGE2_V3_EVALUATION.zh-TW.md)。
新方法效果未知可以是研究問題；必要材料或驗證途徑未知不能冒充可行。
有據零推薦及合理低分可以形成有用交付，但全部淘汰不自動得到高分。

## Stage 2 必須帶到 Stage 3 的選定方向包

- 科學問題、closest work、可能貢獻、增量、邊界及值得研究的理由。
- 初步方法、作用機制、替代解釋、可區辨的觀察／比較與關鍵前提。
- 相關文獻、報告、資料、模型、工具及方法參考的精簡資源表；逐項列
  用途、必要內容／粒度、版本、存取、授權、成本依據、限制及替代方案。
  只列會影響研究問題、方法或可行性的項目，不硬湊所有類別。
- 最小研究、初步時間與資源可行性、共同依賴與合計資源、風險及備案。
- 來源與比較矩陣、支持／反對證據、候選修訂、查核及外部評語、未解
  事項和會改變方向選擇的證據。
- 真實使用者選擇及其候選／報告版本；沿用已存在且驗證通過的交接接口。

「研究交付可讀」「評估完成」「使用者已選定」「Stage 3 執行已授權」
是不同狀態。評分故障仍可交付明示未評完的 proposal，不能稱為已完成
評估；正式 A/B 終點仍在使用者選題指導之前，不能因此要求每次受測 run
都有真人選擇。Stage 3 匯入成功也不自動授權開始研究實驗。

## Stage 3：將選定方向展開為詳細研究規劃

驗證選定方向包 → 明確化可回答的科學問題 → 展開方法及必要時的假設 →
資料處理、樣本／agents、情境與比較設計 → baseline、測量、分析與
驗證設計 → 校準與獨立驗證分離 → 資料／模型／工具及總成本、時間查核 →
最小試驗計畫、排程、風險與備案 → 獨立設計查核及必要問答 → 可編輯
研究 protocol 與 HTML 實際操作 → 使用者確認當前設計 → Stage 4 交接。

這是 Stage 3 開發與驗收要求，不代表詳細 planner 或實驗 executor 已完成。
探索、方法、理論、重複及驗證研究皆可使用，不强迫產生事前假設。
詳細設計發現關鍵不可行時，带證據退回 Stage 2；重要範圍或資源取捨
改變時交使用者決定。實驗執行留給後續已授權的 stage。

## HTML 與交接如何驗收

Stage 2 主畫面優先呈現文獻總覽、主題比較矩陣、方向比較、proposal 與
資源表。書目、原文、查核、外部評分及歷史按需展開；關鍵未知和阻塞
保持可見。採大字、簡短欄位和可用版面，不能讓次要資訊蓋住主要研究內容。

實際打開交付的主入口，檢查頁籤、表格、展開／收合、證據及來源連結、
檔案下載與交接入口；以適用的桌面尺寸及較窄視窗檢查遮擋、文字截斷和
捲動。記錄頁面版本、操作、預期／實際結果及可重查的截圖／工具回執。
schema、文字搜尋或 renderer 單元測試不能代替這項操作驗收。

下一 stage 使用實際交付包做匯入測試；核對所選版本、來源、資源、未知
及使用者決定都能保留。舊版 package 按原契約驗證，不改寫成新版。

## 每個 stage milestone 的驗收紀錄

| 必填項 | 要保存的內容 |
|---|---|
| 範圍與版本 | Stage、run、brief、輸入包、程式／依賴、rubric（適用時）及 hashes |
| 節點結果 | 每個必要節點的輸入、實際呼叫／操作、輸出、結果及證據位置；不適用附理由 |
| 交付物 | 原始 package、可編輯文件、結構化資料及 HTML 一致性查核 |
| HTML 操作 | 主入口版本、實際操作與結果、可追查的視覺／工具證據 |
| 下一階段 | 真實選擇／授權狀態、匯入結果、版本綁定、傳遞限制及未解事項 |
| 失敗與成本 | 未完成、unknown、待覆核、取得／執行失敗、恢復及實際可得用量 |
| 聲明 | 分開標示程式實作、真實 E2E、正式 A/B；缺必要證據不得宣稱完成 |

這是 stage milestone 的要求，不要求每個小工具 PR 重跑完整研究或昂貴
A/B。小 PR 照既有 contributor／PR contract 提供相關測試與誠實的限制；
milestone 才用真實 artifacts 證明整條鏈。後續 stage 在開發前也須明確
定義其輸入、必要節點、交付、HTML 操作與下一階段接口，不臨時補造完成證據。
