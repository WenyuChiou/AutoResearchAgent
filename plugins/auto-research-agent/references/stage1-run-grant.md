# Bounded Stage1 run consent

The trusted Python ProjectStage1RunGrantService records one explicit user consent
for an already confirmed brief and compiled plan. A topic, resource request,
preview or positive budget creates no run authority. The current component has
no public route, launcher dispatch, model, source reader or canonical producer.

The consent binds principal, project, native input version, brief, plan manifest,
complete settings and the trusted server-selected runtime hash. It preserves the
user's verbatim input. Only named Stage1 operations can be authorized; Core,
scientific acceptance, frozen experiments and Stage2 execution stay excluded.

The absolute expiry is at most the saved seconds budget and10800seconds.
An administrative maximum of512 derived actions is separate from research caps.
The existing intake action-history cap also applies. A new key cannot renew the
same binding. Resource limits and reservations remain owned by their existing
query/model/source services; this component never creates or refunds them.

Only a trusted driver can derive an in-process RunActionAuthorization. A matching
JSON object is insufficient. Each downstream adapter must check the same intake,
principal, project, operation and complete payload identity immediately before
its existing admission/transaction and before external work. Saved action
provenance must say user-run-grant and automated actor agent, without pretending
that the user confirmed each individual paper or claim. Until those adapters are
connected, this component alone cannot run Stage1.

Same-key recovery reads the existing intent. Expired, revoked, stale, tampered or
unknown intents cannot authorize new work. A backward wall clock is refused.
The highest observed time and terminal expiry, clock regression or revocation
are committed to a separate private SQLite lease. They survive rollback of an
ordinary intake transaction and a real service reopen. Checks never recreate a
missing or invalid lease. This lease only reduces the original saved consent.
Authenticated revocation uses this attenuation journal even when ordinary
intake history is full; it never removes or resets that history. It attests
neither process cleanup nor a refund. Completing a grant's work never supplies
Core or HTML acceptance.

Temporary SQLite/intake regressions cover these mechanics without native
model, network, source acquisition, research or scientific-quality claims.

Trusted run-derived requests preserve the original consent text and exact payload
identity. Initial grouped agent pending events only record unassessed discoveries;
they never include a paper or attest source quality. A partial Core append stays
execution-unknown and holds later local writes. Canonical semantic adoption and
the default automatic launcher remain separate integration work.
