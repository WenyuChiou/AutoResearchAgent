# Saved Harness and stage operations

This candidate keeps the current main abilities and the reviewed Atlas display,
then adds stage increments from the fixed source
`96460bb6e1bb5a903ce73e5f3d86bebd6bb1de72`. It does not replace main with that
source tree. Native process composition, personal Codex setup and the active
StageModel HTTP fixtures belong to the separate native candidate.

`StagePipeline` prepares hash-bound tasks and preserves attempts, failures,
source identities and incomplete assessments. `StageRunService` owns the durable
permit, shared call/time reservations and explicit task intents. Its neutral
`StageUnitProvider` interface takes an already supplied trusted provider; importing
or hosting this candidate does not create a native runtime. `StageRunHost` adds a
separate execution overlay to the existing graph and binds the final served bytes,
including the landing page, in `host-binding.json`.

The saved-case review example exposes explicit stage checks and reviews:

```powershell
python -B -X utf8 plugins/auto-research-agent/references/research-workspace/examples/build-review-fixture.py --output C:/your/private/new-review --serve --stage-actions --harness-operations --demonstrate-ready-saved-case
```

Open the printed loopback URL. The Stage 1 view can use the same saved public
synthetic coverage ledger and handoff identities whose real gate passes. The
Stage 2 view is an independent saved repository case; it is not derived from that
Stage 1 run. The optional `--demonstrate-stage2-run` adds an explicitly confirmed
fixed SyntheticAdapter worker with real saved controller/review/delivery records.
See [the demo guide](STAGE2_REPOSITORY_DEMO.md). No Codex, model, search, external
judge or new scientific research runs in either example. All synthetic text and
boundaries remain visible.

Refresh and reconnect read history. Same-key actions cannot dispatch again;
uncertain submissions retain their original intent and remain unknown. Selection,
review and a generated partial report do not authorize a next stage. Stage 3–6
remain planned/unconnected. Missing source evidence and independent assessment
remain Unknown or explicitly incomplete.

The pilot contract retains at most eight model calls and 900 seconds only when a
separate exact permit and trusted provider are supplied. Its nine sequential
units can exceed that cap; exhausted budgets therefore remain incomplete. These
engineering bounds are not permission for a new run, a monetary cap or scientific
acceptance. The frozen evaluator, rubric, main Stage 2 recovery fixes and Linux
Engine guards are preserved.

Three active injected StageModel HTTP tests are relocated to the native candidate
instead of importing its future runtime from this saved-stage candidate. The basic
HTTP, durable state, response loss, source drift, time bounds, saved output hashes,
explicit review and UI read recovery are tested here. Windows demo fixture client
and explicit reopened-history waits allow 60 seconds around source checks and
cleanup; the listener remains within its existing 30-second ceiling and the
worker remains bounded to 20 seconds. Actual expiration tests and production
checks remain intact.
