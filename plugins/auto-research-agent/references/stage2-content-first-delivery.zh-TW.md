# Stage 2：先完成研究交付，再放進 Wiki

Stage 2 把文獻變成可討論的研究方向。Stage 3 才安排詳細實驗。
一般使用者只跑 Codex 加研究 harness；正式 A/B 是開發者另外做的比較。

## 先比較，再提出方向

**確認需求 → 讀不同類型的代表文獻 → 整理概念與機制 → 定義比較面向
→ 填入有來源的矩陣 → 綜合機會 → 查核／補查／修訂 → 選擇包 → 使用者選擇。**

比較面向由本次問題和實際文獻共同決定。每欄要回答：對應哪個研究需要、
為何影響選題、如何判斷、哪些條件下可以比較。同名不一定同機制；不同名稱
也可能同設計。研究對象、測量或時間不同時，分組比較並交代界線。
研究 agent 保留原生搜尋、閱讀、程式與子 agent，先自然敘述，再由無工具
擷取器整理；不能為了填格式而補造研究事實。

交付三種互相連結的表：

| 表 | 使用者要知道什麼 |
|---|---|
| 文獻總覽 | 做了什麼、研究誰、用什麼資料和方法、發現與限制 |
| 主題矩陣 | 對選題重要的機制或條件，哪些相同、不同、不可比或尚未知 |
| 方向資源表 | 各方向需要哪些材料、用途、取得條件、限制、備案 |

每個方向說清楚問題、增量、價值、初步方法、最接近研究、替代解釋與改判條件。
保留改良與新概念兩種入口；方法簡單、效果未驗證，都不是淘汰理由。
資料、報告、文獻、模型或工具只列與此方向有關的項目，不硬湊五種類型。
必要變數、粒度、版本、授權、成本與存取未查清楚時保持未知。
縮減方案改變已確認研究範圍時，仍需使用者決定。

## 新的紀錄完整性檢查

Packet 2.2 的 `evaluated-deliver-v3` 使用 presentation **1.3.0**，新增
`content_gate.json`。舊 packet 與 presentation 1.0–1.2 照原規則重播。
同一核心 selection 產生 Markdown、HTML、Wiki 與此紀錄，不另編造內容。

| 檢查 | 缺少時怎麼辦 |
|---|---|
| 有本題矩陣，涵蓋所供文獻 | 顯示 draft；不同類型可用有理由的不適用／未知格 |
| 有比較與目前方向 proposal | 顯示缺的內容，不用空白格推論缺口 |
| 當前方向有五面向查核 | 舊版或缺席查核不能算目前完成 |
| 有相關資源，或材料不適用的理由 | 不以資料網址代替可行性判斷 |
| 推薦的必要資源已記錄取得條件 | 必要條件未知／不可取得時，修正或暫存 |
| 處置、下一步與版本化決策一致 | 不能只填 complete 旗標或舊封包的 hash |

**`content-complete` 只表示這些紀錄齊全。** 它不是科學判斷正確、真實獨立
agent 執行、正式可用或使用者批准的證明。原文身分、語意、獨立初評、補查及
執行紀錄仍由既有 workflow／來源驗證／外部 evaluator 查核。正式選擇包要
完成這些工作；單靠本門檻不能把草稿升級。評分失敗或待真人覆核仍清楚標示。

暫存方向可以紀錄完整；零推薦也可以，但須留下原因與有用的下一步。
高分不代表材料可用。未知、不適用、部分符合與明確不存在分開呈現。
驗收器重建 gate，修改內容後重算所有 hash 仍不能把假狀態變成通過。

## Wiki 閱讀與評估界線

沿用既有 Wiki 主入口：先看比較矩陣，再看方向比較、個別 proposal 與資源。
原文、完整評語與歷史按需展開；重要未知、阻塞與草稿狀態保持可見。
內容改變需要新版本及新評分；只改排版不重發 judge 呼叫。

P4／P5／P6 九項 v3 標準不變，各滿分六分，unknown 為 null，不合成總分。
來源查核和程式測試不等於正式 A/B 改善。兩個真實 B 預演、校準、隔離及投入
政策通過後才做三組配對。必要證據或 Eric 的覆核不足，結果為 inconclusive。
