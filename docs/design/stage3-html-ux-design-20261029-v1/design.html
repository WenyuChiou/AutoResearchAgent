1. 研究者先看到什么

进入页面先回答三件事：我正在看哪个方向和版本、研究准备回答什么、现在最应该做什么。研究内容在前，技术诊断在后。页面顶端保留项目、语言、candidate/version、当前草稿身份和一个主要动作；中段是科学论证与逐题工作；底部才是评审和版本收据。

阅读顺序是：背景与重要性 → 现况/应用与 closest work → gap/挑战 → SQ/意图贡献 → 材料与测量 → 方法/研究设计 → 分析与验证 → 支持/反驳/无法判定 → 最小交付与下一步。原来源没有提供的环节显示具体缺件，不补造文献、科学设计或结果。

不设七个顶层分页。宽屏使用“当前方向／原问题—研究工作区—下一 unknown”层级；窄屏按同一顺序单列。主要阅读区提供四个页内锚点：方向与问题、逐题方案、待解决事项、评审与续接。图/表/卡是同一研究内容的不同读法，不是三份内容。

内容类别在页面中的位置默认展开／重要边界
交付 D01 研究计划方向摘要与论证链原 SQ 和 gap 展开；closest work 保留来源/版本与证据状态
交付 D02 逐 SQ 矩阵主工作区先完整走一题，随后显示其他题；材料用途、适配、测量、设计、分析、三种判读与 blocker 同行
交付 D03 研究图SQ 表附近的辅助读法F03 有明确引用才画；表始终可用；F01/F02 未有结构化来源时显示 future/待补
交付 D04 方案卡每题的设计详情共享方案只定义一次，显示所服务 SQ；保留程序、合法比较/不适用理由、验证、失败与停止条件
交付 D05 资源与 unknown当前下一步与资源详情最近必须解决的 blocker 可见；其余按影响问题分组；owner/日期未知就保留 null/未记录
交付 D06 审查与修订下方“评审与修订”原评语、所评版本与受影响范围；P7/P8/P9 分开，未评为 not-run/null，无总分
交付 D07 可重现与续接下方“按方案继续”同版来源、预定文件、程序/设置/环境需求、下一步；未有代码/数据不称可执行

这里的“交付 D01–D07”与评审指引的“诊断 D01–D09”是不同编号体系。界面以研究者任务命名，不将诊断新增为九个 gate 或总分。

2. 完整使用流程

Stage 2：比较、保存与规划入口

方向比较同时保留原研究问题、材料入口、报告/文献、方法工具、适配限制和 source unknown。材料入口存在、已实际取得文件、适配当前 SQ、具有使用权限四项分开显示。工具可安装不等于材料可用；现有文献结论不等于本研究已观察到结果。

暂定偏好使用“保存方向偏好”，明确 human selection pending。有效正式选案仅在既有合法来源/当前版本和实际人类选择链成立时展示，不用一个勾选框替代该链。合成 mock 不具备真实选择，不能示范成已取得正式接受。

界面保留两个不同意图：“只保存”保持在 Stage 2，并展示保存的是哪个方向/版本；“保存并开始规划”在已保存身份上发起既有显式规划流程并进入 Stage 3。每个具体状态仍只有一个主按钮：比较时主动作为核对方向，明确保存意图后，焦点移至相应保存动作；另一选项为次要动作。两种保存意图不能被合并成含义不清的“继续”。

Stage 3：先读草稿，再处理缺件

1. 首屏核对项目/语言/candidate/version；未能匹配的身份不读取另一项目，也不猜默认选择。

2. 只保存的偏好进入可继续规划状态；prepared 才显示明确确认并开始的动作。运行只使用原 typed request/key/hash，mock 不发任何请求。

3. running 隐去开始控件，主动作是读取已保存状态；不自动轮询、不自动重试、不把“正在运行”画成研究执行中。

4. saved draft 表示规划草稿已保存。先看原问题、方案、原 unknown 和下一处理步骤，再按需看图和技术收据。不是研究完成。

5. needs-information 以当前 source/blocker 定位缺件。点击只定位原 unknown，不创建新 SQ，不把 default_request 不存在的问题改成可运行。

6. 返回 Stage 2 保留项目/语言/方向版本和原条件。reload 走既有只读回读；未完成的 request 不因页面绘制而重发。版本变化清晰显示影响，保留旧稿为历史，按原 owner 规则取得新版本；不自动清空失败或沿用旧 hash。

完整状态规格见 state-matrix.json。same-key/hash 不重复执行是既有工程要求，本设计只规定其可见反馈；该行为的本轮验证为 NOT_RUN。

3. 两个合成案例如何走版面

A. 观察研究：缺测与水质季节差异

布局示例从已保存的方向偏好进入条件式草稿。原 SQ 询问记录覆盖与缺测能否支持季节差异描述；它不是因果效果估计。材料尚未取得且权利未知，页面将“入口已记录／文件未取得／适配待核／权限未知”分别展示。方法和判读来自合成 fixture 中已明示的规划文字；缺少的权属、覆盖与对齐条件继续阻塞，不补一个假通过。

首先阅读 SQ-01 的材料用途、站点/时间粒度和覆盖检查，再看配对时段描述、测量定义、替代解释与支持/反驳/无法判定的边界。计划产物是覆盖与缺测说明及有界的差异描述，实际结果未执行；不画带数值的假趋势图。主动作定位下一项材料适配 unknown，最迟处置时点为 material-design，owner 与日历日期未记录。

条件式结果只有每题材料/方法/设计/分析/判读文本，没有 design_id/analysis_id/result_id 关系。因此 F03 位显示缺少结构化引用并保留完整逐题表；不从 procedure 文本生成图。F01/F02 保持 future/待补。这样没有图也能指出问题、证据边界和下一步。

B. 理论／形式研究：有限图路径约束

第二案例复用同一主次顺序，显示定义/假设、证明义务、反例与边界，不要求数据集、RCT、p-value 或 GPU。该 fixture 是未取得真实选案的结构化草稿布局演示，不是可提交的 ScientificPlan 接收包。

两条 SQ 明确引用同一设计 D-FORMAL-01、同一分析 A-FORMAL-01，分别连接各自最小产物。F03 静态示意仅使用这些明列引用，共享设计画一次并列出服务的 SQ；不将同一证明工作算作两次独立证据。支持只限于假设成立范围；有效反例可反驳全称命题；定义缺失时保持无法判定。

此类 selected-plan view 在基线未保证包含全部 Stage 2 背景与 closest-work 投影。没有同版字段时显示缺件，而不将另一个候选的 context 拼入。未来若需要受 pin 约束的 source-context 投影，由核心 canonical owner 评估；本轮不扩 API。

5. 来源、图、表和方案卡

每次渲染只接收一个 versioned saved-view。先冻结项目、候选/版本、原 question_ref 与 view 版本，再在该对象内部做严格 ID join。视图原子替换，不能保留旧图配新表；渲染中途版本变更时保留旧视图并提示重新读取。

具体指针对照见 source-map.json。该文件区分已有可读字段、仅在结构化计划存在时的字段和基线缺件；不会将 proposed display 字段写回生产 contract。fixtures 中 /view 是 API-shaped 只读对象，/mock_meta 是设计标签；产品指针去掉 /view 前缀。

F03 只画 questions/question_plans/designs/analyses/results 内明列的 ID 引用，不解析自由文字、猜时间顺序或制造因果箭头。节点显示原 SQ/设计/分析/产物，边可读为“此问题由此设计服务／此分析使用此设计／此产物由此分析支持”。缺引用显示缺件并保留原值；不静默修补。

密集时按原 question_refs 分组，共享节点只定义一次，提供“被哪些 SQ 使用”与完整文本对照。未来阅读互动：Tab 聚焦节点，Enter 展开原文，Esc 关闭详情，焦点回节点；图的选中仅定位同版表/卡，不改变项目或 source。F03 候选本轮未取得，以上是互动规格，不是已接入功能。

F01/F02 尚缺 typed 科学路线/程序关系的字段和完整材料。位置保留、标 future/待补，只展示已明确记录的材料/方法目的，不把 Stage2→Python 当科学流程。

6. Unknown、空值和证据状态

空数组表示“没有记录条目”，不是没有未知风险。缺失字段、null、空串、false、0 分别保留：缺字段/空串显示未记录并允许看原值，null 为未知值，false 不消失，已知0不改写为 unknown；费用、数量未知不能用0占位。

source unknown、用户条件、用户 unresolved、missing mapping 与执行不确定性分组，不混成“待完善”。每项显示影响 SQ、所需证据、最迟规划步骤、owner、recheck trigger、fallback 与范围变化。只有来源已有值才填写；没有人名/日期不造一个。before-access-use 与 material-design 是依赖步骤，不是未经依据的日历承诺。

文献已发表结果、草稿已记录的设计、预期产物与本研究实际结果分别标记。not-run/null 保持在实际结果栏；研究尚未执行，不预填效果、成功率、趋势或成本。未来有合法收据的先导可以作为另一版本的实际结果进入，当前不执行先导。

failed 保留原错误和原尝试；提供只读检查/按原规则恢复路径。execution-unknown 不显示重新开始按钮；只有原 owner 的既有 pin/恢复条件成立时才描述显式 recover。读取、回看图、语言切换与刷新均不 dispatch。设计不添加新审批 gate，也不绕过已有确认/eligibility。

7. 本次走查和交付边界

走查按“能否指出方向/版本、SQ材料/方法/产物、证据可支持的范围、下一 unknown 和时点、如何续接”检查。一次 self-review 的 finding、修正和位置保存在 self-review.json，不冒称独立 code review。

实际检查只针对设计产物结构、单一 fixture 引用、明确边、无网络入口、三语言标签与静态 wireframe 边界。真人 usability、真实可及性/浏览器/200%缩放、产品 API/E2E、模型/评审/研究/校准/held-out/正式 A/B、科学有效性为 NOT_RUN；未知数量和费用为 null。

shipping HTML/JS/CSS、Host/assets/registry、部署及 canonical writer 全归核心整合线。本稿只交可读设计、static mock、状态与来源规范，初稿和 self-review 回件后结束，不等待上游。对 #420/#419 的设计 ACK 不构成 merge 或 E2E gate。
